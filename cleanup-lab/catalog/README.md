# Detector catalog

Every target the Cleanup Lab can measure lives here as data. The engine never
hardcodes a path: it loads these files with
[`cleanup_lab/catalog.py`](../engine/cleanup_lab/catalog.py), which validates them
against [`schema.json`](schema.json) and expands the path templates for the
current operating system.

One file per family. `family` must match the first segment of every entry id.

Project sweep signatures live in `signatures/projects.json`, a separate
catalog file validated by `cleanup_lab/artifacts.py`. Each entry names the
artifact directory names, ecosystem, regeneration hint and one or more sibling
or inner marker files. `cachedirTag: true` accepts only a valid `CACHEDIR.TAG`.
This catalog is read-only detection data, not a list of cleanup targets.

`signatures/macos-leftovers.json` defines read-only macOS app inventory and
leftover candidate roots. It is separate from cleanable catalog entries:
findings have confidence and evidence, and cannot be deleted by this API.
`signatures/cross-platform-leftovers.json` defines Linux XDG and Windows
AppData roots for the same report-only confidence model.

| File | Family | Entries |
|---|---|---|
| `system.json` | `system` | User caches/logs, Trash, per-item temp data, crash reports, font caches and Spotlight indexes |
| `browser.json` | `browser` | Chrome, Edge, Brave, Opera, Vivaldi, Firefox and Safari caches; Chrome history and extension traces |
| `developers.json` | `developers` | Developer caches, credential stores and toolchains with per-OS defaults |

CLN-08 stores typed container prune arguments and report-only VM root templates
under `actions/`. The action loader checks argv against an engine allowlist;
these files are not filesystem cleanup entries.

CLN-11's package suggestions are generated by fixed read-only tool calls and
carry typed uninstall argv. They are not filesystem cleanup entries.

Later tasks add `leftovers.json` (CLN-09/10), `packages.json` (CLN-11)
and `simulators.json` (CLN-07/29). [`../PARITY.md`](../PARITY.md) maps every Qleaner detector to its
catalog id or to the reason it was dropped.

## Entry fields

| Field | Meaning |
|---|---|
| `id` | `family.name`, unique across the whole catalog |
| `name` | Short label shown in the UI |
| `category` | `system`, `browser`, `developer`, `project`, `container`, `vm`, `leftover`, `package`, `simulator` |
| `risk` | `low` (regenerable), `medium` (rebuildable, slow or visible), `high` (not a cache), `credentials`, `privacy` |
| `hint` | Why the item exists |
| `impact` | What the user loses or waits for if it is cleaned |
| `defaultSelected` | Whether the item may be pre-ticked. Must be `false` for `high`, `credentials` and `privacy` — the loader rejects the file otherwise |
| `needsPrivilege` | Cleaning it needs a privileged plan (CLN-20) |
| `owningProcesses` | Process names that make the item skip with a reason (CLN-12) |
| `toolName` | Optional executable name checked on `PATH`, without invoking a shell |
| `cleanable` | `false` keeps toolchains visible for scans while the plan refuses cleaning |
| `detector` | `paths` (default), `profile-glob`, `temp`, `spotlight`, `artifacts`, `signatures` or `tool` |
| `cacheEnv` | For `tool` entries, ordered environment variables that may name the cache root |
| `envSuffix` | One directory component appended to an environment cache root, such as `registry` under `CARGO_HOME` |
| `probeArgv` | Fixed arguments permitted only for an entry on the engine's probe allowlist; no shell |
| `note` | Free text for a maintenance caveat |
| `paths` | `macos` / `linux` / `windows` → list of templates. An entry without a path for an OS simply does not appear there |

## Path templates

Developer entries resolve a cache in order: the first valid `cacheEnv` value,
the allowlisted `probeArgv` result (five-second timeout), then the per-OS catalog
default. Empty, relative, multiline, root, home and diagnostic outputs are
rejected. Catalog, scan, plan and result payloads carry `source` (`env:NAME`,
`probe:COMMAND`, `default` or `catalog`) so the chosen location is visible.

`profile-glob` expands the catalog's profile patterns to existing paths. It
includes Default, numbered, guest and other local profiles, while the safety
guard checks each resolved candidate against the literal catalog root and
refuses symlink escapes. Browser entries name their owning process so a running
browser blocks cleaning. History and extension traces are privacy items and
never pre-selected.

The `temp` detector expands each configured root to its immediate files and
folders, omitting symlinks, `.lock`/`.sock`/`.pid` files and regular files below
1 KiB. The `spotlight` detector expands the catalog's `/Volumes/*` template to
indexes on mounted macOS volumes. Shared temp and Spotlight entries are never
pre-selected and require a later privileged flow before cleaning.

`toolName` is an optional executable name checked with `shutil.which` and never
executed through a shell. Shell
functions such as `nvm` and `workon` have no `toolName`: their paths identify
installed data. `cleanable: false` keeps toolchains and local clusters visible
for measurement while the plan refuses deletion.


| Template | Expands to |
|---|---|
| `~` or `~/...` | The user's home folder |
| `{home}` | The same, inside a longer path |
| `{cache}` | `~/Library/Caches` (macOS), `$XDG_CACHE_HOME` or `~/.cache`, `%LOCALAPPDATA%` |
| `{localappdata}` / `{appdata}` | `%LOCALAPPDATA%` / `%APPDATA%` (Windows) |
| `{tmp}` | `$TMPDIR` / `%TEMP%`, `/tmp` elsewhere |
| `${NAME}` | Environment variable. Unresolved (with the name) when unset |
| `${NAME:-fallback}` | Environment variable, fallback when unset or empty |
| `%NAME%` | Windows-style environment variable |

A template that cannot be resolved is **not** guessed: the loader returns
`path: null` plus a `reason`, the scan reports the item as skipped, and the page
shows why. That is rule 4 and rule 6 of the [lab contract](../README.md).

## Checking a change

```bash
cd cleanup-lab/engine && python3 -m unittest discover -s tests -p 'test_*.py'
./labctl cleanup catalog            # this OS, resolved paths and reasons
./labctl cleanup catalog --json     # what GET /api/cleanup/catalog returns
```

`test_catalog.py` checks the catalog against `schema.json` (every required key,
every entry key declared, no strays), so the two cannot drift.
