os-lab · dashboard verification

What the e2e, Playwright and typecheck layers really cover

Three verification layers guard the dashboard, and they cover very different surfaces. This page maps all of them: the full e2e flow from a changed file to an executed spec, every route and locale the specs touch, the run classifications the selector can return, and what the typecheck does and does not see.

Read from dashboard/e2e/affected.json, dashboard/scripts/affected.mjs, dashboard/e2e/*.spec.ts, dashboard/tsconfig.json and dashboard/package.json; counts and timings measured locally on this branch, not inferred.

01 · the e2e flow

From a changed file to an executed spec

Selection is deterministic: one map decides, and the first matching rule wins. The same map drives the local runner and CI, so a branch cannot see a different set of specs in the two places.

The selector is shared code. affected.mjs is imported by scripts/e2e.sh --changed, by dashboard-e2e.yml on a pull request, and by its own unit test scripts/affected.test.mjs — so the three cannot drift without a test failing.

02 · run classifications

Four outcomes, and what each one costs

The selector can only return these outcomes. The distinction that matters operationally is that none and unmapped look similar in a summary but mean opposite things.

ClassificationTriggerSpecs runCI shardsFailure means
none Every changed path matched ignore, or none matched a rule 0 — Nothing to learn; the change is outside the dashboard
some · narrow 1–3 specs selected by rules 1–3 1 The specific view that changed is broken
some · wide 4 or more specs selected 4–12 2 A shared surface broke several views at once
full A path in full: package.json, package-lock.json, playwright.config.ts, tsconfig.json, e2e/affected.json 12 4 Toolchain or test config changed; every view is suspect
some · unmapped A dashboard path matched no rule — falls back to the smoke set and is listed under unmapped 4 + 5 routes 1 A coverage gap: a new view nobody mapped
unmapped is reported locally and dropped in CI. When a dashboard file matches no rule, the selector falls back to the four smoke specs — the run goes green and the new view stays untested. scripts/e2e.sh does print it (unmapped: … (smoke set added; add them to e2e/affected.json)), but dashboard-e2e.yml writes only mode, specs and shards to the step summary, so on a pull request the fallback is silent and the job still passes. Adding a rule is the only thing that closes it.

05 · typecheck

103 source files, one prerequisite that decides pass or fail

npm run check is plain tsc --noEmit under astro/tsconfigs/strict. Run it before astro sync and it reports 26 errors that are all missing generated types — not real defects.

The asymmetry to know: CI runs astro sync && npm run check as one step, so CI can never see the 26-error state. Anyone running npm run check locally on a fresh worktree without astro sync sees a red result that means nothing. The repo's own contributor docs list npm run check without the sync prefix.

06 · layer comparison

What each layer can and cannot catch

The three layers are complementary, but they are not interchangeable, and the gaps are structural rather than accidental.

LayerCatchesCannot catchCost
Typecheck Type errors, missing props, wrong imports across all 103 source files Anything about behaviour, layout, or a route that renders wrongly ~8 s, no browser
Playwright specs Behaviour on the 22 routes they drive: clicks, requests, navigation, error states Routes with no spec; visual regressions (assertions are DOM-based) 1–2 browsers, sharded 1/2/4
Crawl Nothing — it only produces PNGs; a human has to look Everything, unless the images are reviewed 22 routes × 8 locales × 2 widths = 352

Biggest gap

Shared code does not select shared specs

console/** selects every unit stage but zero e2e specs — measured: affected.mjs console/oslab.py returns mode: none. A console change can break every dashboard page and no browser test runs.

Silent fallback

Unmapped means smoke, not failure

A new view with no rule runs the four smoke specs instead. The run is green and the new view is untested; e2e.sh prints the unmapped list locally, but the workflow summary omits it, so the fallback never blocks a PR.

Coverage shape

One spec carries a third of the tests

health-and-content holds 29 of 82 declared tests and drives 12 route families. It is the single point where a flake costs the most time.
